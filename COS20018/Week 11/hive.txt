What is Hive
- High level abstraction on top of MapReduce
- Uses HiveQL language
- Generates MapReduce jobs running Hadoop cluster
- Developed by Facebook, now open-source

`
    SELECT zipcode, SUM(cost) AS total
    FROM customers
    JOIN orders 
    ON customers.id = orders.id
    WHERE zipcode LIKE '63%'
    GROUP BY zipcode
    ORDER BY total DESC;
`

Hive turns Hive query into MapReduce jobs and submits those to cluster
- Hive statements
- Parse HiveQL
- Optimize HiveQL
- Plan execution
- Generate MapReduce jobs
- Submit jobs to Hadoop
- Monitor progress

Benefits
- More productive to use
- Bring large-scale data analysis to broader audience
- No need software developement knowledge
- Leverage existing SQL knowledge
- Extensible through Java
- Supported by BI tools

Loading and storing
- A table is an HDFS directory
- Default path is /user/hive/warehouse/<table_name>
- When table created, metadata is stored in Hive's metastore which is RDBMS like MySQL
- Hive consults the metastore to determine data structure, format and location

RDBMS
- Fast response time
- Support transactions
- Allow records modification
- Allow thousands of simultaneous client requests
Hive
- Have limitations of MapReduce

- Hive tables are stored on HDFS.
- Subdirectories are not allowed.
- A table directory may contain multiple files.
- Hive uses metastore to give context to this data.

hive> SHOW DATABASES;
hive> USE database_name;
hive> SELECT * FROM table_name;

hive> SHOW TABLES;
hive> SHOE TABLES IN database_name;
hive> DESCRIBE table_name;
hive> DESCRIBE FORMATTED table_name;

Complex data type:
- Array: array[index]
- Map: map[key]
- Struct: struct.field

--------------------------------------------------------------------------------

- Data is stored in one or more files.
- Default data format is plain text.
+ One record per line, separated by \n
+ Columns delimited by ^A
+ Complex type elements seperated by ^B
+ Map keys/values separated by ^C
- Hive allow override the delimiters during table creation.

- Hive supports binary formats.
- Pro: better performance.
- Con: limit other programs ability to read data.

- Record Columnar File is binary format created specifically for Hive.
- Column-oriented format is efficient for some queries.
- Otherwise, it is similar to SequenceFile Hadoop-specific binary format.

- Hive databases are simply namespaces.
hive> CREATE DATABASE IF NOT EXISTS database_name;
hive> CREATE TABLE table_name (
        column_name data_type,
        column_name ARRAY<element_type>,
        column_name MAP<key_type, value_type>,
        column_name STRUCTURE<field1: type1, field2: type2, ...>,
        ...
    )
    ROW FORMAT DELIMITED
    FIELDS TERMINATED BY { '\t' | ',' | '|' | ... }
    STORED AS { TEXTFILE | SEQUENCEFILE | RCFILE | ... }

Removal
hive> DROP DATABASE (IF EXISTS) database_name (CASCADE);
hive> DROP TABLE (IF EXISTS) table_name;

Rename
hive> ALTER TABLE old_name RENAME TO new_name;
hive> ALTER TABLE table_name CHANGE old_name new_name new_type new_position;
hive> ALTER TABLE table_name REPLACE COLUMNS (column_to_keep1 type1, column_to_keep2 type2, ...);

Control table data location
hive> CREATE TABLE table_name (column_name1 type1, ...) LOCATION /path/to/table/location;

Self-managed tables whose data remains when table are dropped
hive> CREATE EXTERNAL TABLE table_name (column_name1 type1, ...) LOCATION /path/to/table/location;

View
hive> CREATE VIEW view_name AS SELECT * FROM table_name;
hive> DESCRIBE FORMATTED view_name;
hive> DROP VIEW view_name;

Create table based on existing data
hive> CREATE TABLE table_name AS SELECT * FROM table_name ...;

Write output to file system
hive> INSERT OVERWITE (LOCAL) DIRECTORY /path/to/output SELECT * FROM table_name ...;

Sentry is a plug-in for enforcing authorization.
Sentry can be enabled in HiveServer 2/3 and Impala.
Sentry provides fine-grained, role-based authorization for Hive data and metadata.

What does Sentry control access to: servers, database, table, view
Who can access Sentry-controlled objects: User in a Sentry role=groups
How can role members access Sentry-controlled objects:
- Read operations (SELECT privilege)
- Write operations (INSERT privilege)
- Metadata operations (ALL privilege)
